# 项目一问题记录

> 2026-10-21 审计与复测记录。先前独立 CPU 测试见[脱敏摘录](../tests/evidence/local-api-2026-10-21.md)；原始启动器复测见[端到端记录](../tests/evidence/start-bat-e2e-2026-10-21.md)。本轮运行后，原始启动器重写的 INI 已恢复原哈希。

| 现象 | 已查原因或判断 | 建议与复测证据 |
| --- | --- | --- |
| 旧 `Qwen3.6.bat` 快捷方式可能启动失败 | 其内容调用 `启动.bat`，但安装目录实际文件名为 `start.bat` | 用户确认后修复原始文件，或改用本仓库的示例入口；记录退出码与服务日志 |
| 只有 `ctx = 16384` 无法证明长输入可用 | INI 只是静态配置 | 两模型原始启动器日志均为 `n_ctx_slot = 16384`；近 16K 索引检索答对，合计 16,384 tokens 时日志 `truncated = 1`，不能写无截断通过 |
| 8 GB 显存运行大模型时可能资源不足 | Qwen GGUF 约 10.86 GiB，模型大于物理显存 | 原始启动器 `--fit on` 下两次运行与退出的显存差各约 5 GiB，支持 GPU 使用；准确卸载层数与最佳参数未知 |
| 双击原始启动器可能改动模型目录及配置 | 脚本包含移动 GGUF、硬链接/复制 mmproj、重写 INI 和缺依赖时安装逻辑 | 本轮先备份、审阅再运行原始入口；GGUF 清单无变化，两个改写的 INI 已恢复原哈希；前期的[复现示例](../scripts/llama-oneclick.example.ps1)仍可用于无整理动作的单模型测试 |
| 沙箱运行原始入口在硬件查询时报错 | `Get-CimInstance Win32_ComputerSystem` 无法从受限客户端访问 CIM | 在宿主机权限下重新执行用户指定的原始脚本，成功识别硬件并加载两模型；首次失败未进入模型整理阶段 |
| Qwen IQ2_M 聊天接口正文为空 | 先前 32/128 输出上限被思考占满；本次 `--reasoning on` 长输入在 512 token 上限仍以 `length` 结束、正文为空 | 短请求提高到 512 token 后有可见答复；同一长输入用 `--reasoning off` 后以 9 token 准确返回标记。只说明此场景可绕开空正文 |
| Cosmos 主模型字节一致性待查 | 本机 SHA-256 与 prithivMLmods 同名文件不同；用户确认主模型来自 mradermacher 仓库，补充的具体链接是 mmproj，哈希与本机 mmproj 一致 | 还需比对 mradermacher 仓库中独立的 Q8_0 主文件哈希；见[来源核对](sources.md) |
| Cosmos 历史空间、时序和定位输出有问题 | [会话导出](../tests/evidence/llama-export-audit-2026-10-21.md)关联了实际输入与回复：黄色苹果被当作红色；带英文动作标签的静态拼图被赋予无依据的 0–5 秒时间戳；目标未发现却给全图框 | [多模态审阅](cosmos-multimodal-audit.md)逐项记录；先前仅凭裁剪参考图否定杯子动作依据的判断已更正 |

出现新问题时按“现象、环境、命令、错误原文、判断、处理、复测时间与证据”追加，避免把推测写成已解决事实。
